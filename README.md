Этот файл — справка для владельца сайта (не программиста) и для новой сессии Claude Code, чтобы быстро понять структуру, историю и планы проекта без необходимости пересматривать всю переписку.

## 1. Общее описание

- **Что это сейчас:** временная страница-заглушка главного домена Александра Белякова, пока полноценный сайт не готов.

По сути это тот же сайт по устройству, но с более широким позиционированием (не только Директ, но и Google Ads) и, видимо, дополнительными разделами/услугами — состав будущих разделов пока не определён.

## 3. Google Tag Manager — обязателен на КАЖДОЙ странице

На сайте установлен GTM с ID **`GTM-W7RNPJSZ`**. Это требование владельца сайта: **GTM должен быть на всех страницах без исключений, включая любые новые страницы, которые появятся в будущем.**

При создании новой страницы обязательно копировать оба блока из `index.html`:

1. Скрипт — сразу после открывающего тега `<head>`, как можно выше:
```html
<!-- Google Tag Manager -->
<script>(function(w,d,s,l,i){w[l]=w[l]||[];w[l].push({'gtm.start':
new Date().getTime(),event:'gtm.js'});var f=d.getElementsByTagName(s)[0],
j=d.createElement(s),dl=l!='dataLayer'?'&l='+l:'';j.async=true;j.src=
'https://www.googletagmanager.com/gtm.js?id='+i+dl;f.parentNode.insertBefore(j,f);
})(window,document,'script','dataLayer','GTM-W7RNPJSZ');</script>
<!-- End Google Tag Manager -->
```

2. `<noscript>` — сразу после открывающего тега `<body>`:
```html
<!-- Google Tag Manager (noscript) -->
<noscript><iframe src="https://www.googletagmanager.com/ns.html?id=GTM-W7RNPJSZ"
height="0" width="0" style="display:none;visibility:hidden"></iframe></noscript>
<!-- End Google Tag Manager (noscript) -->
```

**Почему тут GTM, а на `direct` — нет (важно понимать разницу):**
- `direct.alex-belyakov.com` — русскоязычный поддомен, ориентированный на РФ, поэтому там используется Яндекс.Метрика напрямую (подключается через `js/cookie-consent.js` после согласия на cookie, см. его README, раздел 8), а не через GTM. Это осознанный выбор с оглядкой на российское законодательство о персональных данных/рекламе — не путать с этим сайтом и не переносить туда GTM бездумно.
- `alex-belyakov.com` — основной сайт, ориентированный на международную аудиторию. Здесь вместо привязки к конкретным российским сервисам используется **Google Tag Manager как единая точка входа**: все счётчики и коды (аналитика, конверсии, пиксели) добавляются **через GTM**, а не отдельными скриптами в `<head>` каждой страницы.
- Из этого следует практическое правило: **новый код аналитики/трекинга на этом сайте — почти всегда тег внутри контейнера GTM-W7RNPJSZ (в интерфейсе tagmanager.google.com), а не правка HTML.** Править `<head>` страниц нужно только для самого GTM-скрипта (раздел выше) — остальное живёт в контейнере.

## 4. Формы и приём заявок — план на будущее

Форм на сайте пока нет (заглушка их не содержит), но когда появятся разделы с заявками, приём заявок нужно делать **по той же схеме, что и на `direct`** (см. его README, разделы 3–4, и код `js/forms.js`):

- **Сервис приёма:** Web3Forms — тот же принцип, что на `direct`: без бэкенда, POST-запрос из браузера, письмо приходит на почту владельца. Отдельный вопрос — использовать тот же access key, что у `direct`, или завести новый (чтобы разделять заявки по источнику/сайту в личном кабинете Web3Forms). Решить перед подключением первой формы.
- **Общий скрипт валидации** — тот же паттерн, что в `js/forms.js` у `direct`: обязательные поля проверяются на пустоту, `email` — по формату, `phone` — по формату (10–11 цифр), без стандартных браузерных подсказок (`novalidate`), с собственной подсказкой на русском и фокусом на первое незаполненное поле.
- **Honeypot** — скрытое поле-ловушка от ботов, как на `direct`.
- **Согласие на обработку персональных данных** — обязательный чекбокс `consent`, без него форма не отправляется; нужна страница политики конфиденциальности (аналог `privacy.html`).
- **Событие в dataLayer:** при успешной отправке любой формы — `{ event: 'form_sent', form_id: '<id формы>' }`. Поскольку на этом сайте уже стоит GTM (раздел 3), это событие можно сразу использовать в GTM для целей/конверсий — не нужно ждать отдельного подключения аналитики, как было на `direct`.
- **Страницы «спасибо»** — как на `direct`, отдельная `thanks.html` (и, если появится лид-магнит с подпиской, отдельная страница для этого сценария).

## 5. Индексация поисковиками (временно отключена)

Пока сайт — заглушка, индексация в поисковиках **намеренно закрыта**, по той же логике, что применялась к `direct` на этапе подготовки:
- В `<head>` страницы стоит `<meta name="robots" content="noindex, nofollow">`.
- В корне репозитория лежит `robots.txt` с `Disallow: /` для всех роботов.

Сайт при этом работает как обычно — это не блокирует доступ людям по прямым ссылкам, только просит поисковики не добавлять страницы в выдачу. **Когда сайт будет готов к запуску, оба ограничения нужно снять** на всех страницах, иначе сайт так и не появится в поиске.
