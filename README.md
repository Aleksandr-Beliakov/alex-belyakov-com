# Сайт alex-belyakov.com — техническая документация

Этот файл — справка для владельца сайта (не программиста) и для новой сессии Claude Code, чтобы быстро понять структуру, историю и планы проекта без необходимости пересматривать всю переписку.

## 1. Общее описание

- **Что это:** 2026-09-14 сайт был **полностью склонирован с `direct.alex-belyakov.com`** (репозиторий `direct`, состояние на тот же день) — со всей вёрсткой, дизайн-системой, формами и интеграциями. Сделано это намеренно как готовый рабочий каркас: дальше сайт будет постепенно меняться (не только про Яндекс Директ, шире по позиционированию), но пока весь функционал и оформление — точная копия `direct`, чтобы ничего не пришлось собирать заново.
- **Домен:** `alex-belyakov.com` (задаётся файлом `CNAME` в корне репозитория) — отличается от `direct.alex-belyakov.com` у исходного сайта.
- **Репозиторий:** https://github.com/Aleksandr-Beliakov/alex-belyakov-com
- **Хостинг:** GitHub Pages, статический сайт без сборки — чистый HTML/CSS/JS, без npm/фреймворков.
- **Шрифт:** Google Fonts «Golos Text», подключается на каждой странице через `<link>` в `<head>`.
- **Стиль вёрстки:** оформление — инлайн `style="..."` прямо в HTML. В `css/style.css` вынесены только адаптивные media-запросы и несколько именованных компонентов (FAQ-аккордеон, попапы, карусели) — 1-в-1 как в `direct`.
- **Источник:** `direct.alex-belyakov.com` (репозиторий `direct`) остаётся отдельным живым сайтом со своими настройками — см. раздел 9 про то, чем этот сайт теперь **сознательно отличается** от источника.

## 4. Как устроена отправка форм

Полностью как на `direct` — см. его README, разделы 3–4, и код `js/forms.js`. Коротко:

- **Сервис:** [Web3Forms](https://web3forms.com), без бэкенда. **Access key — тот же, что у `direct`** (скопирован как есть, лежит в `js/forms.js`, в документации не публикуется). Это значит, что заявки с обоих сайтов сейчас **приходят в один и тот же почтовый ящик** и внешне неразличимы, кроме поля `subject` (там просто название попапа, без указания сайта). **Надо решить: заводить ли отдельный access key для этого сайта**, чтобы разделять источник заявок — см. раздел 10.
- Обязательные поля проверяются на пустоту, `email`/`phone` — по формату, без стандартных браузерных подсказок.
- Honeypot `botcheck` — защита от ботов.
- При успехе: событие `form_sent` пушится в `dataLayer`, дублируется в консоль браузера и сразу засчитывается как цель Яндекс.Метрики `ym(109844122, 'reachGoal', 'form_sent')` (id счётчика этого сайта — см. раздел 8, отличие от `direct` в разделе 9).
- При ошибке — подсказка «Не получилось отправить, напишите мне напрямую в Telegram» со ссылкой на `t.me/a_beliakov`.

## 7. Индексация поисковиками — полностью закрыта

В отличие от `direct` (там индексация частично открыта, сайт уже зарегистрирован в Яндекс.Вебмастере), этот сайт **пока закрыт от поиска целиком**, потому что это черновой каркас, а не готовый к публикации сайт:

- На всех 8 страницах в `<head>` стоит `<meta name="robots" content="noindex, nofollow">`.
- `robots.txt` в корне — `Disallow: /` для всех роботов без исключений.
- `sitemap.xml` **не скопирован** — не нужен, пока индексация закрыта.

**Когда сайт будет готов к запуску:** снять `noindex` со всех страниц, ослабить `robots.txt` (см. `direct`'s `robots.txt` как пример вида, к которому нужно прийти — но продумать заново, а не копировать бездумно, т.к. у `direct` там же прописаны черновые/архивные страницы `/new.html`/`/pilot.html`, которых на этом сайте нет), завести `sitemap.xml` и подтвердить права на домен `alex-belyakov.com` отдельно — см. раздел 9.

## 8. Внешние сервисы

- **Web3Forms** — приём форм, ключ общий с `direct` (см. раздел 4 и раздел 10 — под вопросом, разделять ли).
- **GitHub Pages** — хостинг. Домен `alex-belyakov.com` подключён через `CNAME` + custom domain в настройках репозитория (HTTPS-сертификат выпускается там же).
- **Google Fonts** — шрифт Golos Text через CDN, без настройки.
- **Google Tag Manager** — контейнер **`GTM-W7RNPJSZ`**, на всех 8 страницах: скрипт сразу после открывающего `<head>`, `<noscript>`-блок сразу после открывающего `<body>` (стандартная установка GTM). **Единственный механизм аналитики на этом сайте** — см. ниже, прямой Яндекс.Метрики здесь больше нет. Новые теги (Метрика, Google Ads, конверсии) заводятся как теги внутри контейнера (tagmanager.google.com), а не правкой HTML. **При добавлении новой страницы** — обязательно копировать оба блока GTM, как на остальных 8.
- **Яндекс.Метрика — намеренно убрана с этого сайта** 2026-09-14 (была унаследована при клонировании `direct`, счётчик id `109844122`). Прямой код счётчика удалён из `js/cookie-consent.js`, вызов цели `ym(..., 'reachGoal', 'form_sent')` удалён из `js/forms.js`. Если Метрика понадобится на этом сайте — заводить её тегом внутри GTM, слушающим событие `form_sent` в `dataLayer` (см. ниже), а не отдельным скриптом. У `direct.alex-belyakov.com` Метрика по-прежнему подключена напрямую (id `111606163`) — это два разных сайта с разной механикой, не путать.
- **Баннер согласия на cookie** (`js/cookie-consent.js`) — остался на сайте, но теперь **ничего не гейтит**: раньше кнопка «Принять» запускала загрузку Метрики, сейчас просто показывает баннер один раз и запоминает согласие в `localStorage.cookie_consent`. GTM грузится сразу, независимо от баннера. Текст баннера общий («сайт использует cookie...») — оставлен как есть, но по сути сейчас чисто информационный. Если он больше не нужен — можно убрать вместе с `<script src="/js/cookie-consent.js" defer>` на всех 8 страницах, но это отдельное решение (см. раздел 10).
- **`form_sent` в `dataLayer`** — при успешной отправке любой формы `js/forms.js` пушит `{ event: 'form_sent', form_id: '<id формы>' }` в `window.dataLayer` (и дублирует в консоль браузера). Это специально оставлено — GTM может слушать это событие как триггер и на его основе запускать любые теги (цели Метрики, конверсии Google Ads и т.д.), не трогая код сайта.
- **JivoChat (виджет чата)** — подключён `<script src="//code.jivo.ru/widget/ufWAawj4Vq" async></script>` на всех 8 страницах, **тот же виджет/аккаунт, что у `direct`** — чаты с обоих сайтов приходят в один и тот же JivoChat-кабинет, внешне неразличимы по источнику. Под вопросом, заводить ли отдельный канал — см. раздел 10.
- **Права на домен (Яндекс.Вебмастер / Google Search Console) — НЕ подтверждены.** У `direct` в корне лежат файлы-подтверждения (`yandex_bdb97dc3a28e4f23.html`, `googlea3d0c6357035dd74.html`) — они принадлежат домену `direct.alex-belyakov.com` и **намеренно не скопированы** на этот сайт. Для `alex-belyakov.com` нужно будет пройти подтверждение заново в Яндекс.Вебмастере и Google Search Console и положить в корень репозитория новые файлы, которые они выдадут (см. раздел 10).

## 9. Чем этот сайт сознательно отличается от `direct` (важно не перепутать)

Сайт скопирован **не байт-в-байт**, часть вещей осознанно изменена при переносе:

1. **Прямой Яндекс.Метрики здесь больше нет** (была `109844122` при клонировании, у `direct` — `111606163`). 2026-09-14 удалена из `js/cookie-consent.js` и `js/forms.js` — на этом сайте вместо неё единая точка входа GTM, см. раздел 8.
2. **Индексация** — здесь полностью закрыта (`noindex` везде + `robots.txt: Disallow: /`), у `direct` индексация частично открыта. См. раздел 7.
3. **Файлы подтверждения прав на домен** — не скопированы (они привязаны к чужому домену), нужны новые. См. раздел 8.
4. **Домен в текстах/мета-тегах** — везде, где в скопированных файлах встречался `direct.alex-belyakov.com` (Open Graph теги `og:url`/`og:image` в `index.html`, ссылка на актуальную версию политики в `privacy.html`), заменено на `alex-belyakov.com`.
5. **`new.html` и `pilot.html`** (рабочий черновик и архив старой версии на `direct`) — **не скопированы**. Это внутренние технические страницы для процесса разработки `direct`, у этого сайта пока нет своей «черновой» версии — когда понадобится, её можно завести по тому же принципу (см. README `direct`, разделы 1–2).
6. **`sitemap.xml`** — не скопирован, не нужен, пока индексация закрыта (см. раздел 7).
7. **`images/face-avatar.jpg`** — не оригинальный файл из `direct`, а версия, сжатая ранее специально для этого сайта (см. раздел 2).
8. **Google Tag Manager подключён здесь и не подключён у `direct`; Яндекс.Метрики здесь, наоборот, нет, а у `direct` она есть.** Изначальный план для этого домена: GTM как единая точка входа для всех тегов (аналитика международная, без завязки на российские сервисы), а Метрика — только у `direct.alex-belyakov.com` как у российского поддомена (см. память Claude Code `analytics_split_direct_vs_main`). При клонировании `direct` целиком контейнер `GTM-W7RNPJSZ` пропал вместе со старым `index.html`, следом клон принёс с собой Метрику `direct`; 2026-09-14 сначала вернули GTM на все 8 страниц, затем убрали унаследованную Метрику — сайт вернулся к изначальному плану: **только GTM**, никакой прямой Метрики. У `direct` — наоборот, только прямая Метрика (id `111606163`), без GTM. Это финальное, осознанное разделение, не промежуточное состояние.
